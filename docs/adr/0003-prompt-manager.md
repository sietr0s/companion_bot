# ADR 0003: каталог промптов в БД

Статус: проект, обсуждение с пользователем.

## Согласованные решения

- Все системные промпты хранятся в БД; файлы служат для seed и явного восстановления.
- Seed добавляет отсутствующие системные записи и никогда не перезаписывает правки.
- Обязательные промпты нельзя удалить, а их служебный код нельзя изменить.
- Пользователь может создавать, редактировать и удалять собственные записи каталога.
- Переназначение промптов сценариям, версии/публикация и привязка к аккаунту/диалогу
  не входят в первую версию.
- Правка начинает действовать со следующего AI-запроса; нет process-local кеша,
  import-time снимков и необходимости перезапускать приложение.
- Шаблоны проверяются перед сохранением; обязательные переменные защищены.
- При недоступности БД запрос завершается явной ошибкой, без fallback на файлы.

## Предлагаемая реализация

Модуль `prompt_manager` владеет ORM-моделью, репозиторием, доменными правилами,
service.py и `routers/manager.py` (одна сущность). Доступ — только admin JWT.
Общий асинхронный порт чтения находится в `src/domain`; composition связывает
его с реализацией. LLM и behavior получают порт через DI, без sibling imports.
Файловый reader остаётся только инструментом seed/reset, без подмены БД в runtime.

Запись: уникальный стабильный `code`, название, содержимое, признак системной записи,
временные метки. Системный признак и исходный ресурс назначаются сервером;
пользователь не может выдавать свою запись за обязательный системный промпт.

Управление: список, создание, изменение, удаление пользовательской записи,
восстановление системной записи из исходного файла. В панели — вкладка «Промпты»,
таблица и редактор текста, ошибки валидации и подтверждение разрушительных действий.
Seed выполняется при startup после создания/миграции схемы, в том числе в safe mode.
Добавляется отдельная миграция; существующая baseline-миграция не переписывается.

## Открытый последний раунд

1. Каталог из всех семи текущих Markdown-ресурсов; техническое форматирование
   сообщений и встроенный embedding query-prefix остаются в Python.
2. Исправить `retrieve_post`, который сейчас передаёт `{query}` и `{messages}`
   буквально; JSON-примеры других промптов не трактуются как переменные шаблона.
3. Reset только одной выбранной системной записи, с подтверждением потери правок.

После ответов на этот раунд подтвердить общее понимание и начать реализацию.
