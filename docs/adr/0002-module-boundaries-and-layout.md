# ADR 0002: границы модулей, слои и организация HTTP/service кода

Статус: принято. Дополняет [ADR 0001](0001-module-consistency.md).

## Обязательное направление зависимостей

**Модуль не импортирует код другого модуля — включая его сервисы, репозитории,
ORM, helpers и schemas.** Это относится и к импорту только для аннотаций типов.

Разрешены собственный код модуля и общие верхние слои:

- `src/domain` — общие доменные сущности и порты;
- `src/base` — generic CRUD, фильтрация, пагинация;
- `src/core` — конфигурация, БД, JWT/permissions, общий manager-router;
- `src/bus` — транспорт и базовые контракты событий;
- `src/utils` — общий код, не принадлежащий конкретному модулю.

`composition/` и `main.py` связывают реализации. Они могут импортировать модули,
а shared/domain/core/base/utils не должны импортировать реализации модулей.
ORM registry находится в `composition/models.py`, а не в `core/database.py`.
Существующие lazy AI-фабрики `composition/ai.py` связывают порты с LLM-модулем;
бизнес-сервис получает уже внедрённый порт и не ищет соседний сервис сам.

Общение модулей — команды/события через шину или внедрённый общий порт.
Контракт, который нужно импортировать нескольким модулям, должен быть вынесен
в общий слой; импорт `neighbor.schemas` не является исключением из правила.

Повторяющуюся инфраструктуру выносим по смыслу: CRUD в `base`, JWT/permissions
в `core`, общие утилиты в `utils`. Не превращаем `utils` в склад бизнес-сценариев
и не вводим абстракцию ради единственного короткого вызова.

## Три уровня данных

1. **Контракты / DTO**: `schemas/api.py` для HTTP и `schemas/events.py` для
   сериализуемых команд/событий. Это входы и выходы транспортной границы.
2. **Домен**: `domain.py` внутри модуля, общие сущности — `src/domain`.
   Сущности, value objects, инварианты; нет ORM, FastAPI или зависимостей от DTO.
3. **Хранение**: `models.py` и `repository.py`. SQLAlchemy-модели остаются
   persistence-деталью. Репозиторий преобразует результат бизнес-запроса в домен.

Отдельный четвёртый набор DTO, копирующий те же schemas, не нужен. Отдельный
`mapping.py` для механического ORM → domain преобразования не нужен: это работа
границы репозитория. Доменная группировка сообщений в Batch — метод HistoryWindow,
а не сериализация API.

В памяти правило применяется к business-сервисам. Generic admin CRUD является
инфраструктурным адаптером: использует общий BaseService/репозиторий и HTTP DTO,
без четырёх пустых наследников CRUD-сервиса на каждую таблицу. Фасад pipeline
валидирует/принимает bus-команду и сериализует событие; внутренние context,
maintenance, indexing и topics работают с доменными данными.

## Роутеры: сначала уровень доступа, затем сущность

```text
module/
  routers/
    __init__.py           # собирает уровни и экспортирует один router
    public/
      __init__.py         # сборка уровня
      sessions.py         # self-service/auth endpoints
    manager/
      __init__.py         # prefix и общая permission policy уровня
      accounts.py         # ручки одной сущности и её auth-подресурсы
      settings.py
      chat_states.py
```

Уровни: `public`, `internal`, `manager`.

- Каждый используемый уровень — папка `public/`, `manager/` или `internal/`,
  даже если сущность одна. Внутри отдельный файл на сущность: например,
  `manager/configuration.py`. Файлы уровня `manager.py` / `public.py` не создаются.
- Файл и папка одного уровня одновременно запрещены.
- `routers/public_accounts.py`, `public_settings.py` и подобные плоские наборы
  запрещены: уровень доступа должен быть явной границей каталога.
- Не создавать пустые `internal`/`public` ради одинаковой структуры.
- `public` — внешний/self-service API, с JWT там, где он нужен конкретной операции.
- `manager` — административные ручки, общая политика `get_current_admin` через
  `core.routers.create_manager_router`. Нет локальных копий JWT-проверки.
- `internal` — только при реальной service-to-service задаче и с явной политикой
  аутентификации. Само имя папки не делает маршрут защищённым.

В текущем приложении маршруты менеджеров исторически имеют `/api/v1/public/*`.
Эта очистка сохраняет URL ради совместимости панели, но раскладывает обработчики
по фактическому уровню доступа. Telegram manager API и auth accounts CRUD теперь
требуют admin JWT; прежняя доступность без токена была отсутствием проверки прав.
Переименование URL-префиксов — отдельная контрактная миграция.

## Сервисы: один вариант структуры

Одна небольшая ответственность — `service.py`. Несколько сущностей/сценариев —
`services/`, с отдельными файлами по сущностям или use cases. **`service.py` рядом
с `services/` запрещён**, даже как compatibility export.

Сервисы не копируют уровни доступа HTTP: domain use case может вызываться из
manager API и из Kafka. Permissions проверяются на входной границе, а не выбором
папки сервиса. Репозиторий содержит SQL; сервис — бизнес-последовательность.

Для memory: `services/pipeline.py`, `context.py`, `maintenance.py`, `indexing.py`,
`topics.py`. Экспорт — из `services/__init__.py`.

## Утилиты и правила

Специфичные helper-функции находятся в `module/utils.py`; большой связный набор
может стать `module/utils/` без одновременного файла. Общие helpers — `src/utils/`.
Семантические инварианты остаются в domain, persistence-типы — рядом с models.
Вызов LLM и запись индекса — сервис indexing, не utils.

Для памяти `clustering.py` удалён: TopicBlock и правила полного непересекающегося
разбиения окна находятся в domain, разбор ответа модели и текстовые helpers — utils.
`mapping.py` удалён. Reference ingestion — явный developer CLI
`scripts/import_reference.py`, не дополнительный runtime-сервис памяти.

## Автоматические проверки

`tests/test_architecture.py` проверяет границы модулей и shared-слоёв, отсутствие
SQL в use cases памяти, отсутствие ORM/API DTO в её внутренних сервисах и domain,
а также соглашения `service.py`/`services/` и уровней routers. Регрессионные тесты
проверяют доменные снимки после закрытия сессии и manager permissions.
Эти тесты входят в обычный CI; нарушение правила не скрывается в quality baseline.

## Иерархическое построение URL

`routers/__init__.py` задаёт только общий API-префикс `/api/v1`.
Пакет уровня доступа собирает свой URL-префикс (`/public` для текущих совместимых
URL), пространство модуля (`/batching`, `/memory` и т.д.) и политику доступа.
Для разделения этих двух сегментов внутри уровня используются вложенные APIRouter.
Файл сущности задаёт локальный путь (`/configuration`, `/accounts` и т.д.)
и относительные пути операций. Полные `/api/v1/...` в файлах сущностей запрещены.
Конфигурационный роутер подчиняется тем же правилам, что остальные сущности.
`main.py` подключает только итоговый router модуля.

Например: `/api/v1` → `/public` → `/batching` → `/configuration`.
Историческое слово public в URL не ослабляет manager permissions.
